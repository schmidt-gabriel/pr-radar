# Developing

Building, running and changing PR Radar. For how it works internally, see
[ARCHITECTURE.md](ARCHITECTURE.md).

## Prerequisites

- Node 22+
- Rust stable
- The [GitHub CLI](https://cli.github.com), logged in

## Running it

```bash
npm install
npm run app        # dev build, hot reload on the frontend
npm run app:build  # bundle it
npm test           # backend tests
```

Bundles land in `src-tauri/target/release/bundle/`: `.app` and `.dmg` on macOS,
`.deb`, `.rpm` and AppImage on Linux. Tauri filters the configured target list
to whatever the host can produce, so the same config works on both.

### Linux build dependencies

Tauri builds against the system WebKit, and the tray needs an AppIndicator
implementation. On Debian or Ubuntu:

```bash
sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file \
  libxdo-dev libayatana-appindicator3-dev librsvg2-dev
```

Fedora uses `webkit2gtk4.1-devel`, `libappindicator-gtk3-devel` and
`librsvg2-devel`. Arch uses `webkit2gtk-4.1`, `libappindicator-gtk3` and
`librsvg`.

TLS is `rustls` rather than `native-tls`, so there is no OpenSSL development
package to chase.

## Project layout

```
src-tauri/src/
  github.rs   GraphQL client and token discovery
  derive.rs   Every rule. Buckets, CI rollup, approval semantics, ordering
  model.rs    The payload the UI receives
  poller.rs   The 60s loop and notification bookkeeping
  lib.rs      Tray, windows, shortcuts, commands
src/
  lib/        Feed subscription, formatting, platform detection
  views/      Popover, Triage, Timeline
  ui/         Shared atoms
  styles.css  Design tokens, and the only place colours are decided
docs/         These files
dev/          Local-only scratch, not shipped
```

## Working on the UI without a Rust build

Dump a snapshot from live GitHub, then run the frontend on its own:

```bash
cd src-tauri && cargo run --example snapshot -- --json > ../dev/snapshot.json
npm run dev
```

Outside the Tauri webview the views load that fixture, so the browser renders
real data with no Rust build in the loop. Add `?window=popover` to render the
popover instead of the triage shell.

The fixture is served by a dev-only Vite middleware and deliberately does **not**
live in `public/`. Everything there is copied verbatim into the production
bundle, and a dump of real pull request data has no business shipping inside the
app.

Without `--json`, the same example prints a readable summary. It is the fastest
way to check the derivation rules against live GitHub:

```bash
cd src-tauri && cargo run --example snapshot
```

## Configuration

The data directory is `~/Library/Application Support/dev.schmidt.pr-radar/` on
macOS, and `~/.local/share/dev.schmidt.pr-radar/` on Linux (or
`$XDG_DATA_HOME/dev.schmidt.pr-radar/` when set).

`config.json` there:

```json
{
  "org": "edsights",
  "label": "Team Review - READY",
  "pollSeconds": 60,
  "notify": true
}
```

| Key | Meaning |
|---|---|
| `org` | organization whose review queue to watch |
| `label` | label marking a PR ready for team review |
| `pollSeconds` | refresh interval, clamped to 10–3600 |
| `notify` | desktop notifications on or off |

`seen-events.json` beside it tracks which events have already been announced.
Delete it to make the next poll re-seed silently.

Hiding partially-approved PRs is a titlebar toggle and persists in the webview.
Sort order (urgency versus oldest first) is a chip in the list header and resets
each session.

Ages are always relative (`3d`, `4h`), computed once in Rust at fetch time.

## Icons

Both icons are generated by pure-Python rasterizers with no image-library
dependency, since none is guaranteed present:

```bash
cd src-tauri/icons
python3 make_tray_icon.py .   # tray.png (macOS template) + tray-color.png
python3 make_app_icon.py .    # app icon: PNG sizes, .icns, .ico
```

`make_tray_icon.py` writes two files. `tray.png` is black-on-alpha at 36px, an
exact 2x of the 18pt height `tray-icon` scales everything to on macOS.
`tray-color.png` is near-white at 48px, for Linux panels where a template image
would be an invisible silhouette.

`make_app_icon.py` renders the squircle and hands the set to `iconutil`. Sizes
at or below 64px get deliberately simplified geometry, fewer rings and heavier
strokes, because the detailed artwork turns to mush when downscaled that far.
The `.icns` step needs macOS; the PNGs and `.ico` are portable.

`dev/iconprev.html`, served by `npm run dev`, shows them at every size against a
checkerboard.

## CI

`.github/workflows/build.yml` has two jobs.

**`check`** runs on every push and pull request, on Linux: frontend build,
`cargo test`, `cargo clippy -D warnings`, `cargo fmt --check`. This is also the
only way the Linux code paths get compiled at all when developing on a Mac,
since `#[cfg]`-disabled code is never type-checked.

**`bundle`** runs only on version tags and manual dispatch, and builds
installers for both platforms. It is gated because macOS runners bill at ten
times the rate, which would drain a private repository's minutes producing
artifacts nobody asked for. macOS builds a universal binary covering both
architectures.

Run it by hand from the Actions tab, or:

```bash
gh workflow run build.yml -f bundle=true
```

## Releasing

```bash
# 1. bump the version in all three places
#    package.json · src-tauri/Cargo.toml · src-tauri/tauri.conf.json
# 2. commit, then tag
git tag -a v0.2.0 -m "PR Radar 0.2.0"
git push origin main v0.2.0
```

The tag triggers a build of both platforms and opens a **draft** release with
the installers attached. Review it, then publish:

```bash
gh release edit v0.2.0 --draft=false
```

`tauri-action` derives the release name from `tauri.conf.json`, so a version
mismatch between the three files shows up there first.

The `bundle` job needs `permissions: contents: write`. Without it the build
succeeds and the release step fails with `Resource not accessible by
integration`, because `GITHUB_TOKEN` defaults to read-only contents.

Builds are unsigned. On macOS that means Gatekeeper blocks the first launch
until the quarantine attribute is cleared. Signing and notarizing is the real
fix if this ever leaves your own machines.

## Gotchas

- **The Vite port is pinned with `strictPort`.** Tauri's `devUrl` is a fixed
  address, so letting Vite fall back to the next free port silently loads
  whatever else is running on 5173 into the app window. It refuses to start
  instead, which is the correct failure.
- **Anything in `public/` ships.** Vite copies it verbatim into the bundle.
- **Release asset names use `PR.Radar`, not `pr-radar`.** GitHub substitutes the
  space in the product name.
